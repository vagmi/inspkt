# inspkt — Roadmap

> Generated by /onboard. Check off phases as they ship. Each phase is a vertical
> slice and ends deployable. Source of truth for product scope: `prds/base.md`.

## What we're building
An org-scoped inspection platform: define custom inspection forms (the rubric),
register the things you inspect, capture inspections in the field with photos
and geo-tags, and get an automatic, explainable verdict (pass / conditional /
fail) with corrective actions and re-inspection scheduling.
**Users:** teams within companies — form authors/admins, field inspectors,
reviewer/managers (one person may play all roles in Phase 1).
**Core resources:** items (inspectable registry) · forms + checkpoints ·
inspections + observations · corrections / re-inspections.
**First journey:** register an item → inspect it against a form → get a verdict.
**Billing:** full paid plans via Polar (free tier with limits, paid unlock).

## Phases

### [x] Phase 0 — Finish environment setup
**Goal:** `pnpm doctor` green; app runs locally with sign-in.
**Build:**
- Create a Clerk app at dashboard.clerk.com and **enable Organizations**
  (the app is org-scoped and will not work without it).
- Fill `CLERK_SECRET_KEY` + `CLERK_PUBLISHABLE_KEY` in `.dev.vars` and
  `VITE_CLERK_PUBLISHABLE_KEY` in `.env.local` (both files already copied from
  the examples; never commit them).
- Run `npx wrangler d1 create inspkt` yourself (needs browser login — type
  `! npx wrangler login` first if needed) and paste the printed `database_id`
  into `wrangler.jsonc`.
- `pnpm db:migrate:local`, then `pnpm doctor && pnpm typecheck && pnpm test`.
**Done when:** doctor is green; `pnpm dev` serves the app; you can sign in and
create an organization. (App already renamed mudhal → inspkt. ✓)

### [x] Phase 1 — Inspectable item registry
**Goal:** an admin/inspector can register the things that get inspected, with a
geo-tagged location, and browse them.
**Slice:** evolve the existing `items` slice (it *is* this resource) — schema
`workers/api/db/schema/items.ts` (add `category`, `location_lat`,
`location_lng`, `location_label`) → `workers/api/repositories/items-repo.ts` →
`workers/api/services/items-service.ts` → `workers/api/controllers/items-controller.ts`
→ route `app/routes/app/items-list.tsx` (+ create/edit with location capture).
**Build:** follow the copy-`items` recipe in `docs/workshop.md §2` — here it's
an in-place extension rather than a copy. New migration; update the mirrored
tests in `tests/repositories|services|controllers`.
**Done when:** sign in → register an item with name, category, location → see
it in the list; `pnpm test` green; deploys.

### [ ] Phase 2 — Inspection form builder
**Goal:** a form author can create a reusable rubric: named form with ordered
checkpoints grouped into sections.
**Slice:** schema `forms` + `checkpoints` (answer type: pass-fail / numeric
ranges / rating threshold / observation; `critical` flag; severity
minor/major/critical; `photo_required`; `section` + `position` for ordering)
→ forms-repo → forms-service (validate checkpoint configs, e.g. numeric ranges
must be coherent) → forms-controller (zod schemas for each answer type) →
routes `app/routes/app/forms-list.tsx` + `forms-edit.tsx` (builder UI).
**Build:** copy the `items` slice per `docs/workshop.md §2`; two tables, one
sub-router. Org-scope every query; `requireCapability` for authoring.
**Done when:** create "Quarterly HVAC Check" with mixed checkpoint types, save,
reopen, edit; tests green; deploys.

### [ ] Phase 3 — Inspection capture (with photos)
**Goal:** an inspector picks a form + item, walks the checkpoints, answers each
with notes and photos, geo-tags the inspection, and saves draft or submits.
**Slice:** schema `inspections` (item_id, form_id, inspector user id, status
`draft|submitted`, captured lat/lng, timestamps) + `observations` (checkpoint_id,
answer payload, note, per-observation lat/lng, photo keys) → inspections-repo →
inspections-service (draft/resume/submit rules; photo-required checkpoints must
have a photo to submit; flag location mismatch vs. item's registered location)
→ inspections-controller → route `app/routes/app/inspections-capture.tsx`
(mobile-friendly checkpoint walker using browser geolocation).
**Build:** first run `pnpm install-skill r2-uploads` for photo storage (adds
its own keys to `.dev.vars`), then the copy-`items` recipe for the two tables.
Attribute the inspector via `c.var.userId`.
**Done when:** start an inspection → answer checkpoints with a photo + note →
save draft, resume, submit; status becomes `submitted`; tests green; deploys.

### [ ] Phase 4 — Verdict engine + follow-up generation
**Goal:** every submitted inspection automatically yields an explainable
verdict and the follow-up it demands. This is the core of the product.
**Slice:** schema `corrections` (inspection_id, checkpoint ref, deadline,
status open/closed) + verdict fields on `inspections` (score 0–100, verdict
`pass|conditional|fail`, `reinspection_due_at`) → repo additions →
**verdict-service** (pure functions: per-checkpoint resolve → pass/warn/fail;
critical-item override; severity-weighted score; tier thresholds; corrections
for conditional, re-inspection date from worst severity for fail) → wire into
inspections-service `submit` → controller exposes verdict → capture route shows
the verdict + "why" immediately after submit.
**Build:** the engine is deterministic service-layer logic — no Hono imports,
exhaustively unit-tested in `tests/services/` (same inputs ⇒ same verdict).
**Done when:** submitting a fixture inspection with a failed critical
checkpoint yields Fail with a re-inspection date regardless of score; a minor-
issues-only one yields Conditional with corrections; tests green; deploys.

### [ ] Phase 5 — Inspection report
**Goal:** a manager/auditor can open a structured, print-friendly report for
any completed inspection.
**Slice:** no new tables — service-level report assembly (inspection + item +
form + observations + photos + verdict + corrections) → controller `GET
/inspections/:id/report` → route `app/routes/app/inspection-report.tsx` with
verdict badge, section-by-section results (failures highlighted), photos in
context, corrections + re-inspection date; print stylesheet.
**Done when:** open any submitted inspection → full report renders on screen
and prints cleanly; tests green; deploys.

### [ ] Phase 6 — Lifecycle dashboard
**Goal:** the loop closes: nothing overdue gets lost.
**Slice:** extend inspections schema/status to `… → reinspection_scheduled →
closed` + repo queries (open inspections, recent verdicts, **overdue
re-inspections**, overdue corrections, items with latest verdict) → dashboard-
service → dashboard-controller → route `app/routes/app/dashboard.tsx` as the
app landing page; actions to close corrections and start a due re-inspection
(pre-linked to the same item + form).
**Done when:** a failed inspection shows up with its re-inspection date; once
past due it appears in "overdue" without searching; closing corrections moves
the inspection to closed; tests green; deploys.

### [ ] Phase 7 — Billing via Polar
**Goal:** paid plans: free tier with limits, paid plan unlocks the operation.
**Slice:** `pnpm install-skill billing-polar` (adds checkout, webhooks, billing
route, `POLAR_ACCESS_TOKEN` to `.dev.vars`) → define plans in the existing
`getPlan(plan)` pattern (suggested: free = 2 forms, 10 items, 20 inspections/
month; pro = unlimited — tune before launch) → enforce in services:
forms-service/items-service check `getPlan(plan).max*` at create;
inspections-service meters submits via `usageRepo.increment` → upgrade CTA in
the UI when a gate trips.
**Done when:** a free org hitting a limit gets a clear upgrade prompt; checkout
upgrades the plan and the gate lifts; tests green; deploys.

### [ ] Phase 8 — Production deploy
**Goal:** inspkt live on Cloudflare.
**Build:** per `docs/workshop.md §3` — `wrangler secret put` for every server
secret (Clerk, Polar, R2), remote D1 migrations, `pnpm deploy`, switch Clerk to
a production instance and point webhook URLs (Clerk org-sync, Polar) at the
production domain; smoke-test the first journey end to end.
**Done when:** sign in on the production URL → register an item → inspect it →
verdict + report; dashboard shows it.
